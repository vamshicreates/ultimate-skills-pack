# Screenplay shot lists and storyboards

Produce a complete, traceable shot plan and matching image boards. A storyboard is a proposed visual interpretation of the screenplay, not a claim that the script specifies every camera choice. Honor the user's format, style, references, scope, and budget when supplied.

## Read and index the script

1. Read the entire supplied screenplay, including title material, action, dialogue, parentheticals, transitions, montages, intercuts, and ending. Extract text from PDF/DOCX/FDX/Fountain as appropriate. For a scanned PDF, OCR and flag uncertain passages; never silently treat failed extraction as an empty scene.
2. Preserve source page and line or paragraph anchors. Inventory every scene heading in order. Give unnumbered scenes stable IDs (`S001`, `S002`, ...); preserve printed scene numbers separately. Include opening material that lacks a slugline and identify ambiguous scene boundaries. Maintain a scene coverage ledger with source span, scene summary, characters, location, time, and completion status.
3. Read each line in context and map its action, dialogue, or sound cue to a scene beat. Several lines can share a shot; one line can motivate several shots. Do not force one shot per screenplay line. Account for every beat without inventing a new story event. Mark implicit visual choices as proposals.
4. For long scripts, work in ordered scene batches while keeping the same inventory, character bible, location bible, shot IDs, and output files. Resume from the ledger; do not label a partial batch as the complete film.

## Design coverage

For each scene, write as many shots as the dramatic action needs. Give each shot a stable ID (`S001-SH001`) and record the screenplay anchor, covered beat/dialogue, shot size, camera angle and height, camera movement, subject/blocking, composition and screen direction, lens or focal-length intent when useful, lighting/mood, and reason for the choice. Note any insert, reaction, POV, cutaway, or transition that is needed for editorial clarity. Avoid redundant coverage and unfounded technical precision. Keep geography, eyelines, axis, props, wardrobe, and time of day coherent. See [shot design](references/shot-design.md) when making complex camera or edit decisions.

Create a character continuity bible before image generation. Separate script facts, user references, and chosen visual interpretations; never present inferred appearance as scripted fact. Record stable appearance, costume by scene, distinctive props, and relationships. Also record recurring location and visual style. Use user-provided reference images where available. Lock one shared art direction. Default to **black graphite pencil and fine pen lines on white paper, using only neutral grays for shading**; when the user requests color, lock a palette and rendering style instead. Apply it to character references and all storyboard images. Record `style` as `monochrome` or `color` in `storyboard_manifest.json`.

## Count, estimate, and confirm before generation

Complete the scene inventory and shot plan first, without generating images. Count scenes, visual shot panels, recurring characters needing a new reference image, and **three-panel sheets** (normally `ceil(scene_panels/3)` within each scene). One generated 16:9 image contains up to three sequential panels from one scene, so the **baseline number of image-generation calls is sheet images plus new character reference images**. Propose a separate, explicit maximum number of correction calls and show the maximum authorized calls. If the user supplied usable character references, do not count new reference images for those characters. Roughly 15–20 sheets can cover a group of two or three substantial scenes, but this is a target, not a quota; keep enough panels for the story and use fewer for shorter scenes.

Give a realistic **time range** for script analysis, reference creation, sequential shot generation, visual review/corrections, board assembly, and final PDF QA. Show the assumptions: planned calls, expected per-call latency or the current published model guidance, rate limits if using the API, and review time. The built-in tool does not reveal a fixed future quota or predictable latency; label the estimate provisional and update it after the first completed batch. Do not promise an exact finish time or background completion.

Present the count, maximum calls, board count, time range, and final PDF contents to the user and **ask for confirmation before the first image-generation call**. The shot plan is reviewable at this point. Record the approved count, call ceiling, estimate, and actual calls in `production_plan.json`. Once confirmed, continue through the approved calls without asking again for each batch. If the shot count or call ceiling must increase materially, show the revised count and obtain a new confirmation before exceeding the approved ceiling. Keep all completed work and the ledger if generation is interrupted.

## Generate storyboard frames

Use the available built-in `image_gen` tool by default, following the installed `imagegen` skill. After confirmation, generate and lock a style-matched canonical reference portrait/full-body view for each recurring character who lacks a supplied reference. Record each final reference image in the manifest. Keep the same canonical reference and written identity traits for every later scene; a prior storyboard sheet can supplement this reference but must not replace it. Work through the screenplay in ordered groups of two or three scenes, generating **one 16:9 triptych image per group of up to three consecutive shot panels within one scene**. Generate a few sheets, inspect them, then continue; do not submit a blind bulk request for the whole film.

Use the relevant canonical character references and, where helpful, the accepted prior sheet as image inputs. Prompt each **landscape 16:9 sheet** as exactly three clearly separated sequential visual panels when three beats exist: panel 1 is a wide top panel, panel 2 is bottom-left, and panel 3 is bottom-right. Give each panel its own shot ID, subject/action, framing, camera angle, composition, screen direction, and relevant dialogue beat. This layout leaves the bottom two panels landscape and supports a wide establishing image above them. Use one or two panels only when the scene ends with fewer meaningful beats; never invent filler shots merely to reach three. For monochrome, require hand-drawn graphite pencil and fine pen on white paper with neutral gray shading only. For color, use the approved palette and medium consistently. Ask for no in-image captions or dialogue; add numbered shot labels and camera notes during sheet assembly.

Inspect all three panels for the requested count and order, legibility at the intended PDF size, face, hair, body shape, costume, geography, props, action, angle, framing, and approved visual style. Correct drift, wrong panel count, or unwanted color in monochrome boards with a focused image edit and the same canonical references, within the approved correction allowance. If only one panel fails, edit that sheet while preserving the other panels. If three panels remain illegible or inconsistent after reasonable corrections, use fewer panels per sheet and obtain approval before exceeding the call ceiling; do not upscale a weak image and call it high quality. Treat consistency as a review target, not a guarantee; flag unresolved mismatches. Save selected final sheet images in the project output folder; keep prompt and reference paths in the manifest. Do not replace existing assets without the user's instruction.

Finish each triptych as a **3840×2160 sheet** in the approved style. Preserve the generated art without cropping and place three matching shot IDs, camera notes, and short action captions in a white footer outside the art. Each sheet remains 16:9 and contains one to three panels; do not place 15–20 tiny images on one page. Use [deliverable format](references/deliverables.md) and `scripts/compose_board.py` for exact sizing and labels. In the PDF, place one sheet per page; a two- or three-scene group may therefore occupy about 15–20 pages when its planned panels justify that many sheets.

## Scale, limits, and completion

Build one final `storyboards.pdf` containing the character continuity bible, every final character reference image, the complete scene-by-scene shot list with camera notes, and **every three-panel sheet** in order. Give each 16:9 sheet its own PDF page so the sketches remain legible. Use `scripts/build_pdf.py` and the PDF skill's render-and-inspect workflow. Keep individual sheet files as editable supporting assets. The PDF is the primary final deliverable.

A fixed number of images per screenplay page is not defensible; derive the count from the shot plan. Use draft quality and smaller images for visual exploration when supported, then render selected finals within the approved call ceiling. The built-in image tool does not expose an advance token quota or a guaranteed exact size, so do not claim a fixed allowance; check current tool/API limits if relevant and log actual usage when available. If using an explicitly authorized API path, respect its current rate limits and costs, retry only transient failures with backoff, and stop on quota exhaustion with a resumable ledger. Do not silently omit shots or substitute text placeholders for requested images.

Before delivery, run `scripts/validate_project.py <project-folder> --final` and audit that every source scene appears in the ledger and shot list, every storyboard panel maps to a source beat and appears once on a sheet, each sheet has one to three panels and is 16:9, the PDF contains all sheets, captions match camera choices, the art matches the approved monochrome or color style, and recurring characters remain visually consistent. The script checks file and ID bookkeeping; it cannot prove script interpretation, exact panel separation, or identity consistency. Report uncertain extraction, unrendered shots, or continuity exceptions explicitly. Deliver the PDF and retain the shot list, bible, manifest/ledger, source triptychs, and finished sheets as supporting files.
