# Optional reference-script calibration

Use supplied reference screenplays to clarify standards and interpret specific craft mechanisms. This is contextual calibration, not model training, permanent memory, or evidence that imitation will succeed. A new session needs access to the saved rubric and reference notes.

## Build a reference library

For each reference, record title, source file, language, genre, format, runtime/timing basis, evaluation unit, draft/version, reading completeness, relevant scene locators, and what the user admires or dislikes. Prefer comparable durations and units when establishing expectations. A feature scene may illustrate compressed emotion in a micro-drama, but a feature's full character arc is not its required benchmark. For series, separate episode execution from cumulative season execution. Distinguish user-reported hit status from verified commercial data; there is no need to research earnings or viewer metrics to assess craft.

Read references in full before making whole-script claims about them. If only scenes were read, label them as scene-level examples. Do not assume a shooting draft matches the released film or fill screenplay gaps with memories of performances, editing, music, or direction.

Successful films can demonstrate useful execution, but success alone does not establish screenplay quality. If the collection is all hits, document that selection bias and proceed. Do not make additional unsuccessful films a prerequisite. Varied genres, languages, scales, and user annotations can improve the usefulness of the library.

## Save actionable calibration

Maintain a `calibration-profile.md` in the user's chosen evaluation output folder with:

- The rubric ID, weights, date, and intended audience/language context.
- User-stated preferences, separated from the evaluator's inference.
- Evidence-backed examples of effective and ineffective execution, with locators and the mechanism each illustrates.
- Scope: where each example transfers usefully and where genre, culture, or form makes transfer uncertain.
- Disagreements, unresolved interpretations, and confidence limits.

The profile is a reusable record, not a collection of copied screenplays. Quote only what is needed for analysis. Keep the source material separate from this skill's repository.

## Apply references without a halo effect

1. Freeze the evaluation rubric before assessing the candidates. If reference calibration changes the rubric later, version it and rescore all affected candidates before comparing.
2. Assess each candidate independently first. Do not treat resemblance to a hit as a quality criterion. Reduce reputation bias where practical by ignoring awards, earnings, and promotional labels; do not call the assessment blind if the work is recognizable.
3. Add a reference comparison only when it explains a concrete mechanism: preparation of a reversal, relationship progression, withholding of information, use of silence, or another relevant choice.
4. Identify what transfers and what does not. A genre-specific device is not a universal requirement, and a famous ending does not authorize copying its expression.
5. If a reference changes the interpretation of the candidate, revisit the underlying evidence and explain the score revision. Do not add a “similar to a hit” bonus.

Where useful, separate **craft assessment** from **fit with the user's taste**. Keep taste fit qualitative by default. If the user requests a numeric taste-fit score, label it separately and never quietly fold it into the craft total.

## Calibration checks

Revisit an anchor example when scores drift across a long batch. Re-read the actual relevant scenes rather than relying only on old summaries. If enough references exist, a held-out reference can help reveal whether the rubric overfits a small set of favorites, but do not claim a small exercise validates audience prediction.
